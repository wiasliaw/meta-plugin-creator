# Constraints

## C-001: Progressive disclosure

- **Rule**: Plugin content (this plugin, and every plugin it produces) MUST follow progressive disclosure: a lean entry file (`SKILL.md`, command) that defers detail to referenced files loaded on demand.
- **Source**: Founding requirement — keeps context small and instructions followable.
- **Applicability**: All skills, commands, and agents authored in or generated by this plugin.

## C-002: State externalization

- **Rule**: Plugins MUST externalize all cross-step state into a declared state-filesystem layout (documented file paths), and MUST NOT keep state only in conversation context.
- **Source**: Founding requirement — enables harness engineering: inspection, resume, and verification from outside the session.
- **Applicability**: Any plugin behavior that spans more than one step or session.

## C-003: Context cleanliness via delegation

- **Rule**: Plugins MUST delegate heavy or noisy work to sub-agents or a claude-team rather than running it in the orchestrating context.
- **Source**: Founding requirement — keeps the main context clean.
- **Applicability**: Whenever a task produces bulk output (search sweeps, file dumps, batch edits) that the orchestrator does not need verbatim.

## C-004: Git worktree compatibility

- **Rule**: Plugins MUST function correctly inside a git worktree — they MUST NOT assume `.git` is a directory or hardcode the primary checkout path.
- **Source**: Founding requirement — worktree-based workflows are first-class.
- **Applicability**: Any plugin logic that touches git state or repository paths.

## C-005: Down-tier model support

- **Rule**: Plugin instructions MUST be executable by lower-tier models, supported down to Opus: explicit steps, no reliance on implicit inference or unstated conventions.
- **Source**: Founding requirement — produced plugins must not require the top model tier to work.
- **Applicability**: All plugin content.

## C-006: Pure markdown, no runtime dependencies

- **Rule**: Plugin content MUST be pure markdown / static files; it MUST NOT introduce runtime dependencies (npm packages, binaries). Dev tooling for release (changesets) is exempt.
- **Source**: User-declared — keeps plugins installable anywhere Claude Code runs.
- **Applicability**: Everything under plugin source; `devDependencies` for release tooling are exempt.

## C-007: English plugin content

- **Rule**: All skills/commands/agents content MUST be written in English.
- **Source**: User-declared — lowers misinterpretation risk for lower-tier models and keeps the plugin shareable.
- **Applicability**: All plugin source files; repo docs follow the same convention.

## C-008: Entry-file line budget

- **Rule**: A `SKILL.md` MUST NOT exceed 500 lines; overflow MUST be split into reference files.
- **Source**: User-declared — hard backstop against context bloat, complements C-001.
- **Applicability**: Every `SKILL.md` in this plugin and in produced plugins.
